# Society

Society is a game that simulates a vilage on an island. This includes people living there, going about their day-to-day lives, working, having children, interacting with facilities in the vilage (hausing, workplaces, civic buildings). The goal of the player is to make the society flourish - for the village to expand in the number of people it can support, for the people to be happy and to be able to susten the upkeep of the village. The player will have to raise money via taxes on the working population in order to build facilities.

## Implementation details

Read README.md in the root of the repo folder for details on how projects in this repo are managed.

The game is implemented as a single self-contained `index.html` file (except for binary resources) using plain JavaScript and an HTML5 canvas for rendering. Additional binary resources (such as graphics) should be placed in a `resources` subfolder. Open `index.html` in a browser to play. Rendering runs on `requestAnimationFrame`. An 80ms interval timer drives animation frames; a full game turn is committed once every 5 such frames (every 400ms), with NPC movement interpolated across the intervening frames.

For debugging, the running simulation state (board, NPCs, facilities, camera, clock) is exposed on the global `window.society` object so it can be inspected from the browser dev console.

## Gameplay

The game is played on a board of 100x100 tiles. The user sees a portion of this board (top-down view; as many tiles as can fit onto the screen) and can zoom-in, zoom-out and pan across the board (see "Keyboard Actions" section for key assignment). The board starts with a randomly generated landscape. The generation of the landscape is described in the "Board Generation" section.

The board consists of landscape tiles and the board is generated at the begining of the game (see "Board Generation" section). Characters (NPCs) can move over these tiles and facilities (building) can be built over them. Each board tile is one of these. A NPC takes-up a single tile. Facilities can take up multiple tiles. Two NPCs cannot occupy the same tile at the same time. NPCs can enter a facility. Facilities have "capacity" which is the maximum number of NPCs that can be in the facility at the same time.

Each NPC can move one tile per game turn (horisontaly or vertically). The movement of the NPC is dictated by the NPC state machine.

## Landscape Tiles

Each tile is one of the following landscapes:

- Ocean - NPCs cannot move onto ocean, buldings cannot be built over ocean.
- Grassland - NPCs can move over these tiles and building can be build on these tiles
- Woods - NPCs can move over these tiles and building can be build on these tiles
- Mountains - NPCs cannot move onto mountains, buldings cannot be built over mountains.

## Tile Graphics

Each landscape tile type is drawn from a PNG bitmap stored in the `resources` subfolder. The bitmaps are generated by the script `resources/generate_tiles.py` (see "Generating tile graphics" below).

Sprite format:

- Each sprite is a **96x96 RGBA PNG**.
- The central **64x64 region (the "core") is fully opaque** and maps exactly onto one board tile.
- The core is surrounded by a **16px overhang** on every side (16 + 64 + 16 = 96). The overhang's alpha fades smoothly from fully opaque at the core edge to fully transparent at the sprite edge.
- Because two adjacent tiles each overhang 16px toward each other, their faded borders overlap across a **32px band** and blend together, hiding hard tile seams.
- Ground textures (ocean water, grass, rock) receive the overhang alpha fade.
- **Features** (such as trees or mountain peaks) are drawn on top at full opacity and may extend slightly beyond the core edge into the overhang, so they can spill a little over neighbouring tiles.

Tile sprite files:

- `ocean.png` - water with wave/foam texture.
- `grassland.png` - plain grass texture.
- `woods-1.png`, `woods-2.png`, `woods-3.png` - grass with trees. Multiple variations exist so woods tiles have visual variability; the renderer picks one at random per woods tile. The chosen variation is fixed once when the board is generated so it stays stable across turns.
- `mountains.png` - grass with a snow-capped rocky peak feature.

### Rendering

When drawing the board, each tile's sprite is scaled so its 64x64 core covers the tile exactly; the surrounding 16px overhang is therefore drawn spilling a quarter of a tile beyond each edge. Tiles are drawn from top-left to bottom-right so that lower and right-hand tiles (and their features, such as trees) blend over the tiles behind them. Until a sprite bitmap has finished loading, the tile is drawn as a flat fallback colour.

### Generating tile graphics

The sprites are produced by `resources/generate_tiles.py`, a Python script that uses the [Pillow](https://python-pillow.org/) imaging library. To (re)generate the PNGs:

```
python -m pip install Pillow
python resources/generate_tiles.py
```

The script writes all sprite PNGs into the `resources` folder. It builds each sprite by rendering a procedural ground texture, applying the 16px overhang alpha fade (a smoothstep ramp from the opaque core to the transparent sprite edge), then compositing any feature layer (trees, peaks) on top at full opacity. Generation is seeded so output is reproducible, and the woods variations use different random seeds and tree counts/sizes.

## Board Generation

- start with all Ocean tiles
- pick 5 random locations and update tiles within a radius of 20-50 tiles (choose randomly) to Grassland
- pick 20 random locations (on grassland) and change tiles within a random radius of 4-15 tiles to Woods
- pick 7 random locations (on grassland) and change tiles within a random radius of 3-12 tiles to Mountains


## Keyboar Actions

- zoom-in: PageUp or + (plus)
- zoom-out: PageDown or - (minus)
- pan left: A or left-arrow
- pan right: D or right-arrow
- pan up: W or up-arrow
- pan down: S or down-arrow

The game starts fairly zoomed in (32 pixels per tile). Zoom ranges from 2 pixels per tile (fully zoomed out) to 96 pixels per tile (closest zoom).

## Mouse Controls

The **mouse wheel** zooms in and out, centred on the cursor position.

Clicking the game window does two things: it selects the NPC or facility under the cursor (see "Inspecting Objects"), and it **locks the mouse** to the window. While the mouse is locked, a crosshair cursor is drawn at the pointer position and the following apply:

- Moving the cursor near an edge of the window scrolls the map in that direction (edge scrolling).
- Clicking selects the object under the crosshair.
- Clicking a button in the properties overlay (its close or delete button) while the crosshair is over it activates that button.
- Pressing **ESC** releases the mouse lock.

## Touch Controls

On a touch screen:

- **Drag** one finger to pan the map.
- **Pinch** with two fingers to zoom in and out (the zoom is centred on the midpoint between the fingers).
- **Tap** to select the NPC or facility you tapped (see "Inspecting Objects").

## NPCs

The board state (including NPC tile positions) only updates once per turn (every 400ms). The movement of an NPC from its previous tile to its new tile is animated in between turns: the screen is redrawn every 80ms (5 animation frames per turn) and the NPC's drawn position is linearly interpolated from its previous tile to its new tile across those frames.

Two NPCs cannot occupy the same tile. If an NPC's intended move is blocked by another NPC, it waits that turn.

### Game Clock and Day Cycle

The game keeps a clock measured in turns. A full day is 120 turns (48 seconds of real time). The current day number and an in-game time of day (HH:MM) are shown in the on-screen HUD, along with a population breakdown. A day/night tint darkens the whole scene, deepest at midnight and absent at noon.

The day/night cycle does not control NPC behaviour directly; instead it modulates the thresholds at which the needs in the NPC state machine trigger (see "NPC State Machine"). This keeps NPCs mostly - but not strictly - aligned to the cycle: they tend to eat by day and sleep at night, but a pressing need is acted on whatever the time.

### NPC State Machine

An NPC has multiple properties, each with a value from 0 to 1000. The values of these properties drive the NPC's behaviour. They change according to the rules in this state machine and through interactions with facilities around the map.

**NPC Properties**

- fullness
- alertness

The values are shown as a percentage (0-100%) when an NPC is inspected (see "Inspecting Objects").

The sections below list the NPC state machine rules.

#### Hunger Rule

The "fullness" of an NPC decreases by two points each turn. If "fullness" falls below the current food threshold, the NPC heads straight for the nearest food source (a facility that can replenish fullness - an orchard). If "fullness" reaches 0, the NPC dies.

#### Sleep Rule

The "alertness" of an NPC decreases by three points each turn. If "alertness" falls below the current rest threshold, the NPC heads straight for the nearest place to rest (a facility that can replenish alertness - a house). If "alertness" reaches 0, the NPC dies.

#### Day/Night Thresholds

The "below threshold" levels in the hunger and sleep rules are not fixed; they swing with the day/night cycle so that NPCs stay mostly aligned to it without being strictly bound to it.

Each threshold is computed as `max(300, 200 + 700 * factor)`, where `factor` runs from 0 to 1 across the cycle. So a threshold swings between **300** (its floor) and **900** (its peak):

- The **rest** threshold uses the "night factor" (0 at noon, 1 at midnight), so it is **900 at midnight** and falls to its **300 floor by noon** - NPCs strongly tend to head to a house to sleep at night.
- The **food** threshold uses the opposite (1 at noon, 0 at midnight), so it is **900 at noon** and falls to its **300 floor by midnight** - NPCs strongly tend to head to an orchard to eat during the day.
- Because both thresholds are floored at 300, the survival rules above (a need below 300) always apply regardless of the time of day.

If both needs are below their thresholds at once, the NPC acts on the more depleted one first. When neither need is pressing, the NPC wanders.

Needs start between 700 and 1000 when an NPC is created. An NPC inside a facility leaves once the need being restored reaches **980** (nearly full), or sooner if its other need becomes the more urgent priority.

#### Movement and Facility Use

When an NPC needs a facility it moves one tile per turn along the shortest path (breadth-first search over terrain and buildings, ignoring other NPCs, which move) toward the nearest facility of the required type. Reaching the facility's entrance it enters if there is spare capacity, otherwise it loiters nearby. While inside, the relevant need is replenished each turn; the NPC leaves once that need is nearly full, or sooner if its other need becomes the more urgent priority.

NPCs that are inside a facility are not drawn on the board; their presence is reflected in the facility's occupancy count. NPCs out on the board are drawn as coloured dots reflecting their state: amber while seeking/eating food, blue while seeking/taking rest, grey while idle (no pressing need).

#### Death

When an NPC's fullness or alertness reaches 0 it dies. A dead villager is not removed from the world: it remains on the board at the tile where it died, drawn as a static grey body with a dark cross, and no longer moves or has needs. The population count in the HUD drops and a "Dead" count appears.

## Facilities and Buildings

Facilities can be located anywhere on the board, take up a rectangular set of tiles, and NPCs cannot move over the facility, but they can enter and exit them. NPCs interact with facilities to replenish their properties. On the board, facilities are displayed as semi-transparent rectangles with an icon in the top-left corner identifying the type of the facility. Each facility also has a **capacity** (the maximum number of NPCs that can be inside at once) and shows its current occupancy as an `occupants/capacity` badge in its bottom-right corner.

A facility has one **entrance** - a walkable tile adjacent to its footprint - which NPCs path to in order to enter. The footprint tiles themselves are solid and block movement. NPCs inside a facility are not drawn on the board; their presence is reflected in the occupancy count.

Below is the list of available facilities.

### Orchard

- Size: 3x3 tiles
- Icon: 🍎
- Capacity: 6

When an NPC enters an orchard, its "fullness" is replenished by 15 points per turn.

### House

- Size: 2x2 tiles
- Icon: 🏡
- Capacity: 4

When an NPC enters a house, its "alertness" is replenished by 15 points per turn.

### Seeding the Board with Facilities

At game start the board is seeded with **7 houses** and **5 orchards**, scattered around the map. To make sure NPCs can always reach the buildings, seeding happens on a single landmass: the largest connected region of walkable tiles is found first, and all facilities (and NPCs) are placed within it.

Each facility is placed by picking a random spot in that region whose footprint is entirely on buildable land and not overlapping another building, and which has a free adjacent walkable tile to serve as the entrance.

## Inspecting Objects

Clicking an NPC or a facility opens a property overlay on the right-hand side of the screen showing details of that object. The overlay updates live while it is open.

- For an **NPC** it shows its **fullness** and **alertness** (each as a percentage with a bar).
- For a **facility** it shows the facility **type**, its **capacity**, and the current number of **occupants**.

While the overlay is open, the inspected object is marked on the board with a pulsing gold **focus indicator** (a ring around an NPC, or a rectangle around a facility) so it is clear which object is being tracked. If the inspected NPC is currently inside a facility, the indicator highlights that facility instead, so the focus follows the NPC indoors.

Only one overlay is shown at a time: clicking a different object switches the overlay to that object's properties rather than opening a second overlay. Clicking empty terrain leaves the current overlay unchanged. The overlay has an **X** button in its top-right corner to close it, which also removes the focus indicator.

Because NPCs are small, moving targets, a click does not need to land exactly on an object. If the clicked tile is empty, the nearest object (NPC or facility) within about 1.5 tiles of the click is selected, with closer objects winning. This effectively searches the neighbouring tiles outward from the click. NPCs win ties against a facility at the same distance.

### Deleting Facilities

When a facility is selected, it can be deleted - either by pressing the **Delete** key or by pressing the **🔥** button in the properties overlay. Deletion asks for confirmation first. When a facility is removed, its tiles become walkable land again and any NPCs that were inside it are turned out onto those tiles. (NPCs cannot be deleted.)
